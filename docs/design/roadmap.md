# Markdown Vault MCP roadmap

This is agent-authored synthesis, not a record of decisions. Tag each
argument `stated` (the user's words), `derived` (synthesis), or
`evidenced` (with a durable locator). Read the
[`roadmapping` skill](../../.agents/skills/roadmapping/SKILL.md) before
charting or refining work.

Epics are parent issues for stories; packages are milestones for single
release cuts. GitHub holds membership, dependencies and progress. This
index holds the argument for the direction and order.

## Direction

Add one short entry per epic, linking its issue and frozen "Done when"
outcome. Explain the ambition without inventing implementation detail.

## Packages

List intended cuts in order as `NNN name (major/minor/patch)`, each
linked to its milestone with one sentence explaining the order. Use
ordinals with gaps, such as `010` and `020`; kind is intent, and the
release version is computed from what lands. Select "Alphabetical" on
GitHub's Milestones page to see title order.

Do not copy item lists or progress here. An issue with no milestone is
backlog; commit it to a package when it should ship in that cut.

## Known unknowns

Give each unknown a resolved-by pointer to an issue or epic. When an
answer changes what happens next and no planned work answers it, link a
research issue with an appetite. Otherwise explain why recording it is
enough.

## Revisions

Record dated changes of direction and their reasons here.
