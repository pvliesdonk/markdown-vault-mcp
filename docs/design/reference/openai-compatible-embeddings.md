# OpenAI-compatible embedding responses

This page records what the shared OpenAI-compatible transport
(`_OpenAICompatEmbeddings` in `src/markdown_vault_mcp/providers.py`) can rely
on in an embeddings response, and how one vendor departs from the OpenAI
shape. It covers the response only; the request shape and the fields strict
vendors refuse are in `docs/design/design.md`, § `providers.py`.

## Scope

- Covers: the per-item `index` and `embedding` fields, the order of `data`,
  how the `openai` SDK reads an item that lacks a field, and Gemini's batch
  responses.
- Does not cover: request fields, error bodies, token limits, other vendors'
  response quirks.
- Depended on by: `src/markdown_vault_mcp/providers.py`
  (`_OpenAICompatEmbeddings.embed`), `docs/design/design.md` § `providers.py`
  ("Response order").

## Claims

### The OpenAI shape

- An `Embedding` object has `index` (integer, "The index of the embedding in
  the list of embeddings"), `embedding` and `object`, and all three are
  `required`. [source: openai-openapi]
- `CreateEmbeddingResponse.data` is "The list of embeddings generated by the
  model". The schema states no order for that list, so `index` is the only
  documented link from a vector back to its input. [source: openai-openapi]

### How the openai SDK reads a response

- The SDK types `Embedding.index` as `int`. [source: openai-python-embedding]
- The SDK builds response models with `construct`, which does not validate:
  a field absent from the JSON is set to the field's default instead of
  raising. [source: openai-python-models]
- For an item with no `index`, that default is `None`, so `item.index is None`
  even though the type says `int`. [observed: openai 3.50.0, the version
  `uv.lock` pins, 2026-11-14: `client.embeddings.create` against an
  `httpx.MockTransport` returning Gemini's shape gave indexes
  `[None, 1, 2]`] [observed: openai 3.46.0 inside the
  `ghcr.io/pvliesdonk/markdown-vault-mcp:latest` image, server 6.1.1,
  2026-11-14, calling `OpenAIProvider.embed` on three texts against Gemini;
  the sort raised "'<' not supported between instances of 'int' and
  'NoneType'"]

### ProtoJSON

- A field without presence that holds its default value should be omitted
  from the JSON output; an implementation may offer an option to emit it.
  For an integer, the default is 0. [source: protojson]

### Gemini's compatibility endpoint

- The base URL is `https://generativelanguage.googleapis.com/v1beta/openai/`,
  embeddings go through `client.embeddings.create`, and the documented models
  are `gemini-embedding-2` and `gemini-embedding-001`. The page calls the
  OpenAI library support "still in beta" and documents no difference in the
  embeddings response. [source: gemini-openai]
- In a batch response, the first item of `data` has no `index` key; every
  later item carries its index, 1, 2, and so on. A raw response to the input
  `["a", "b", "c"]` was
  `[{'object': 'embedding'}, {'object': 'embedding', 'index': 1}, {'object': 'embedding', 'index': 2}]`
  with the `embedding` values left out here. [observed: curl against the
  base URL with model `gemini-embedding-2`, 2026-11-14; the same shape for
  two inputs with `gemini-embedding-001`, 2026-11-11, reported on #2050]
  [pins: tests/test_providers.py::TestOpenAIProvider::test_embed_treats_missing_first_index_as_zero]
- `data` arrives in input order, and the item without `index` is input 0.
  [observed: a five-text batch to `gemini-embedding-001` compared with each
  text embedded alone, cosine 1.000000 at every position, 2026-11-11,
  reported on #2050; three texts to `gemini-embedding-2` the same way,
  2026-11-14]
- A one-item response never carries `index`, since its only index is 0.
  [observed: single-text requests in the same runs]
- The response observed for two inputs has the top-level keys `object`,
  `data` and `model`, with no `usage`. [observed: the 2026-11-11 raw
  response reported on #2050] The transport does not read `usage`.
- That the missing key comes from a ProtoJSON serialiser is an inference:
  only the zero value is dropped, which matches the rule above, but Google
  does not document how the layer serialises. [unverified] A Google statement
  or a non-zero field observed missing would settle it.

## Where this project departs from the subject

The transport sorts `data` on `index`, reading a missing `index` as 0, which
is ProtoJSON's meaning for an omitted integer. Before #2050 it sorted on the
raw value, and comparing `None` with `1` failed every Gemini batch of two or
more; a one-item batch, such as a search query, had nothing to compare and
worked.
[pins: tests/test_providers.py::TestOpenAIProvider::test_embed_sorts_by_index, tests/test_providers.py::TestOpenAIProvider::test_embed_treats_missing_first_index_as_zero]

An endpoint that omits every `index` gets its vectors in response order,
because the sort is stable and every key is 0.
[pins: tests/test_providers.py::TestOpenAIProvider::test_embed_keeps_response_order_when_no_index]
